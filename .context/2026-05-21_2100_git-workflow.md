## Branches

| Branch | Propósito | Merge de | Merge para |
|---|---|---|---|
| `main` | Produção — código estável e taggeado | `release` (via PR) | — |
| `release` | Staging/QA — candidatos a release | `develop` (via PR) | `main` |
| `develop` | Integração — feature branches se encontram aqui | `feature/*`, `fix/*`, `hotfix/*` | `release` |

### Branches temporárias

```
feature/<escopo>-<descricao-curta>   # Nova funcionalidade
fix/<escopo>-<descricao-curta>       # Correção de bug
hotfix/<descricao>                   # Fix crítico em produção (sai de main)
refact/<escopo>-<descricao-curta>    # Refatoração
```

**Exemplos:**
```
feature/auth-register-endpoint
fix/patient-soft-delete
hotfix/jwt-expiration-crash
refact/backend-exception-handling
```

## Convenção de Commits (Conventional Commits)

### Formato

```
type(scope): descrição em minúsculas (imperativo, max 72 chars)

[corpo opcional — explica o porquê, não o quê]

[footer opcional — BREAKING CHANGE, closes #issue]
```

### Tipos

| Tipo | Quando usar |
|---|---|
| `feat` | Nova funcionalidade |
| `fix` | Correção de bug |
| `refact` | Refatoração sem mudança de comportamento |
| `test` | Adicionar ou corrigir testes |
| `docs` | Documentação |
| `style` | Formatação, sem mudança de lógica |
| `perf` | Melhoria de performance |
| `chore` | Build, dependências, config |
| `ci` | Mudanças em CI/CD |
| `hotfix` | Correção crítica em produção |

### Escopos

`auth` | `user` | `patient` | `nutritionist` | `avaliation` | `billing` | `security` | `db` | `frontend` | `config` | `ci`

### Exemplos

```
feat(auth): adiciona endpoint de registro de usuário
fix(patient): corrige soft delete não persistindo archivedAt
refact(security): centraliza exception handling com @ControllerAdvice
test(auth): adiciona testes de integração para login e refresh
chore(deps): atualiza spring-boot para 4.0.3
ci: adiciona workflow de CI para pull requests
feat(frontend): implementa formulário de login com validação
```

## CI/CD (GitHub Actions)

### `ci.yml` — Acionado em:
- Push em `develop`
- Pull Request para `develop`, `main` ou `release`

**Jobs:**
1. `backend` — Maven build + testes com MySQL container
2. `frontend` — npm ci + lint + type-check + build

### `release.yml` — Acionado em:
- Push em `main`

**Jobs:**
1. Extrai versão do `pom.xml`
2. Cria tag Git `vX.Y.Z`
3. Cria GitHub Release com notas geradas automaticamente

## Fluxo de Trabalho Típico

```
1. git checkout develop && git pull origin develop
2. git checkout -b feature/<escopo>-<descricao>
3. [desenvolve, commits pequenos e descritivos]
4. git push origin feature/<escopo>-<descricao>
5. Abre PR → develop
6. CI passa? → merge squash no develop
7. [quando pronto para release]
8. Abre PR develop → release
9. QA/testes → merge
10. Abre PR release → main
11. CI passa → merge → tag automática
```

---

## Regras (configurar no GitHub)

- `main`: require PR + CI passing + 1 review + no direct push
- `release`: require PR + CI passing
- `develop`: require CI passing
