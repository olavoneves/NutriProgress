## O que foi implementado no Day 2

### Estrutura criada
```
com.nutriprogress.modules.auth/
├── controller/
│   └── AuthController          (POST /auth/login, /register, /refresh, /google)
├── service/
│   ├── AuthService             (login, register, refresh, buildLoginResponse)
│   ├── JwtService              (Auth0 java-jwt — generate, validate, extract)
│   └── GoogleOAuthService      (verificação de ID token + criação automática)
├── dto/                         (todos records: Login/Register/Refresh/Google/Token)
├── security/
│   ├── JwtAuthenticationFilter
│   ├── JwtAuthenticationEntryPoint
│   └── UserDetailsServiceImpl
└── exception/
    ├── InvalidCredentialsException
    ├── TokenExpiredException
    └── UserAlreadyExistsException
```

### Configurações
- `config/JwtProperties` — bind `jwt.*` do yml (secret, expiration, refresh-expiration, issuer)
- `config/SecurityConfig` — reescrito (deixa de ser stub permitAll). Filter chain JWT, CORS, public endpoints `/auth/**` + actuator + swagger, BCrypt, AuthenticationManager via AuthenticationConfiguration
- `shared/exception/GlobalExceptionHandler` — estendido para auth (InvalidCredentials, TokenExpired, UserAlreadyExists, JWTVerification, BadCredentials)
- `pom.xml` — adicionado `google-api-client 2.2.0`. **Auth0 java-jwt 4.5.1** mantida; JJWT do prompt original **NÃO** usada.
- `application.yml` — `jwt.issuer` + `google.oauth.client-id`

### Decisões importantes
- **JWT lib:** Auth0 java-jwt (já estava no pom). API: `JWT.create()...sign(Algorithm.HMAC512(...))` / `JWT.require(...).build().verify(token)`.
- **Repositories:** mantidas as assinaturas existentes (`findByEmailIgnoreCase`, `existsByEmailIgnoreCase`).
- **DTOs:** todos como Java `record` (não classes Lombok @Data).
- **ApiResponse/ErrorResponse:** records já existentes do Day 1 reutilizados, **não** recriados como Builder.
- **Specialty:** enum standalone (`com.nutriprogress.modules.nutritionist.entity.Specialty`).
