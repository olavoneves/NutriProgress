# Arquitetura Técnica — NutriProgress
**Data:** 2026-05-21 22:00 (pós-Day 1)
**Descrição:** Decisões arquiteturais e padrões adotados na refatoração

---

## Princípios

1. **Monolito modular** — cada módulo em `modules/{nome}/` (entity, repository, service, controller, dto)
2. **Clean architecture** — Controller → Service → Repository
3. **DTOs ≠ Entities** — nunca expor entidades JPA diretamente
4. **Soft delete** — coluna `is_active` em vez de DELETE físico
5. **Auditoria** — `createdAt`, `updatedAt`, `createdBy`, `updatedBy` em todas as entidades via `AuditableEntity` + `@EnableJpaAuditing`
6. **Paginação** — `Pageable` em listas (não retornar `List<T>` para coleções grandes)
7. **Bean Validation** — em DTOs (Day 3+), não em entities

## Banco — Convenções

- **PKs:** `UUID` com `gen_random_uuid()` (Postgres) ou `GenerationType.UUID` (JPA)
- **Timestamps:** `TIMESTAMP` (Postgres) ↔ `LocalDateTime` (Java)
- **Datas:** `DATE` ↔ `LocalDate` (ex: `birth_date`, `evaluation_date`)
- **Decimais:** `DECIMAL(precision, scale)` ↔ `BigDecimal`
- **Enums:** `VARCHAR(50)` + `@Enumerated(EnumType.STRING)` — nunca ORDINAL
- **JSON:** `JSONB` + `@JdbcTypeCode(SqlTypes.JSON)` (suporte nativo Hibernate 7)
- **Soft delete:** `is_active BOOLEAN NOT NULL DEFAULT true`

## Relacionamentos

```
User (1) ↔ (1) Nutritionist  [User é inverso, Nutritionist é dono via user_id]
Nutritionist (1) → (N) Patient
Nutritionist (1) → (N) Evaluation
Patient (1) → (N) Evaluation (com unique constraint patient_id + evaluation_number)
```

**Trigger PostgreSQL:** `set_evaluation_number()` auto-incrementa `evaluation_number` por paciente antes de cada INSERT em `evaluations`.

## Tratamento de Erros

`GlobalExceptionHandler` (@RestControllerAdvice) mapeia:

| Exceção | HTTP | Origem |
|---|---|---|
| `ResourceNotFoundException` | 404 | services |
| `UnauthorizedException` | 401 | auth (Day 2) |
| `ValidationException` | 400 | regras de negócio |
| `MethodArgumentNotValidException` | 400 | Bean Validation em DTOs |
| `Exception` (catch-all) | 500 | inesperado |

Resposta padrão: `ErrorResponse` (status, error, message, path, fieldErrors[], timestamp).

## Pontos de Atenção / Decisões

1. **Hibernate 7 nativo** para JSON em vez de hypersistence-utils (uma dependência a menos)
2. **Flyway** está com `baseline-on-migrate: true` — útil em dev, considerar `false` em prod
3. **`open-in-view: false`** — evita LazyInit fora de transação; força carregar relacionamentos no service
4. **`ddl-auto: validate`** — schema controlado por Flyway, não Hibernate
5. **AuditorAware no Day 1 retorna empty** — `created_by`/`updated_by` ficam null até auth real entrar
